# Resource planning integration

Implement the requested business workflow within SmartCivi's authenticated, role-controlled MySQL platform. Preserve Bongabong branding, existing records, resident modules and the stock/allocation ledger. Do not replace persistence with local storage or bypass authentication. Resource officers and administrators receive planning access; resident staff keep their existing boundaries.

1. Extend resources additively with location, personnel status and contact number. Retain legacy codes and conditions, generate immutable codes when omitted, and accept Good/Fair/Poor alongside the existing operational conditions. Low stock is derived from supply quantity/threshold. Continue to adjust stock through the ledger. Add confirmed archive/restore, list CSV and printing.
2. Add a dedicated Personnel page using existing category=personnel Resource rows. Support name, position, department, contact and Active/On leave/Inactive status; search, edit, archive/restore, CSV and print. Count active personnel independently from current assignment availability. No duplicate employee database.
3. Add Budget entries with department, item, fiscal year, allocated and spent amounts using precise decimal peso values. Provide CRUD with archive/restore, search, fiscal-year filtering, CSV and printing. Aggregate allocated/spent/remaining and usage by department; flag overspending, including spending against zero allocation.
4. Enrich dashboard and planning reports with active personnel, resource categories, fiscal-year budget summaries and a Needs attention list for overspending, Poor/unserviceable equipment and low stock. Apply role guards to every route and export.
5. Provide a sidebar System Diagrams page showing one existing structural/behavioral SVG at a time, with validated selection, download and print. Label historical documentation accurately; it does not prove current runtime behavior.
6. Add new planning tables to encrypted backups, preserve older archive compatibility, test additive migration and existing record retention. Verify forms, monetary arithmetic, overspending, active counts, stock restrictions, permissions, CSV/print/downloads and desktop/mobile layouts. Review before delivery; do not push without request.

Independent planning work in models/Planning.js, services/planning.js, routes/planning.js and dedicated views/tests. Existing diagrams are read-only artifacts.
